# GPT：基于因果 Transformer 的生成

GPT风格的模型使用一个仅解码器的Transformer来预测下一个标记。这里，“仅解码器”意味着没有单独的源编码器和其交叉注意力块的因果自注意力。不同模型代际之间，精确的归一化、激活、位置编码和训练选择各不相同。

## 完整的预测路径

```mermaid
flowchart LR
    T[标记ID] --> E[嵌入和位置]
    E --> B[因果Transformer块]
    B --> L[词表 logits]
    L --> P[下一个标记分布]
    P --> S[解码一个标记]
    S --> T
```

对于标记 $x_1,\ldots,x_T$，训练通过最小化 $-\sum_t\log p_\theta(x_t\mid x_{<t})$ 来优化目标。在强制教师训练期间，所有目标位置可以并行评估。在生成时，所选的输出成为下一个输入的一部分。

## 预测是一个分布

给定 `法国的首都是`，假设模型将概率 0.8 分配给 `巴黎`，将概率 0.1 分配给 `里昂`，并在其他地方分配 0.1。贪婪解码选择 `巴黎`；采样可以选择另一个标记。温度和截断修改解码分布，而不是存储的模型权重。参见 [解码](../inference/decoding.md)。

基础模型训练继续文本。指令调优和偏好优化教给对话行为和响应偏好。它们是额外的训练阶段，不是因果掩码的直接后果。

## 缓存的重要性

过去的关键和值可以重用，因为过去的某个位置不能读取未来标记在因果模型中。新的查询仍然需要与相关的历史进行交互，因此缓存可以节省重复工作，而不会使上下文长度自由。内存和注意力成本随着存储上下文的增加而增长。

## 评估正确的事物

困惑度衡量标记化文本上的预测拟合情况。它不直接测量指令遵循、事实可靠性、工具使用或长上下文检索。在适当的情况下，使用相同的分词器/任务协议比较模型，并报告生成设置。

**练习。** 如果生成的响应是错误的，注意力掩码必须也是错误的吗？不一定。数据限制、解码、缺失上下文或学习到的关联即使在正确实现时也可能产生错误。
