# LangChain：围绕显式状态构建模型应用

LangChain 提供了模型应用、集成、工具和代理工作流的抽象。它的 API 在不断发展，因此请固定包版本并查阅已安装版本的文档。持久的教训是使数据流动和副作用显式化。

## 分离组件

模型预测消息或工具调用。检索器返回候选证据。工具执行定义的操作。协调器决定输出如何流向后续步骤以及何时停止执行。对话状态记录工作流需要继续的内容；它不是对持久真相的替代。

一个简单的检索应用可以在没有自主代理的情况下表达：

```text
问题 -> 检索段落 -> 组装证据 -> 生成答案 -> 验证引文
```

代理循环添加了基于模型的选择下一个动作。这种灵活性在路线不能提前固定时很有用，但它也要求迭代限制、错误处理和对中间操作的可见性。

## 实际支持工作流

对于支持助理，首先使用确定性的文档搜索路径。如果任务需要，再添加一个查找工单的工具。将工单标识符、检索来源和工具结果保留在结构化状态中。如果需要写入操作，将其表示为具有明确授权和重试行为的独立操作。

当前的 LangChain 文档将 `create_agent` 表示为可配置的代理接口。LangGraph 提供了更低级别的工作流协调，而 LangSmith 支持跟踪/评估。选择抽象层次，使应用程序的控制流程易于理解；不需要采用每个组件。

## 评估行为而不是框架使用

记录检索质量、工具调用的有效性、任务成功、延迟、成本和失败恢复情况。一条追踪应该显示错误是否起源于检索、模型选择、工具执行或最终合成。避免仅因为跟踪方便而记录敏感内容。

提供抽象并不使所有模型都相同。消息格式、流事件、结构化输出和工具架构可以有所不同。测试实际的提供者、模型、包版本和中间件组合。

**练习。** 将函数包装为工具是否使其安全重试？不是。幂等性取决于函数做什么。搜索和工单创建需要不同的重试策略。
