# DeepSpeed 与 ZeRO：分布式管理训练状态

DeepSpeed 是一个深度学习优化系统。ZeRO，其零冗余优化器家族，减少了数据并行工作节点之间的重复训练状态。名称为 DeepSpeed；它与 DeepSeek 模型系列分开。

## 为什么权重不是整个内存账单的全部

训练存储权重、梯度、优化器状态、激活和临时缓冲区。像 Adam 这样的优化器维护两个动量估计，通常在 FP32 中，并且混合精度配方也可能保留主权重。一个推理权重可以完全适应一个设备的模型，在训练期间仍然可能超过其内存。

普通的数据并行复制每个工作节点上的模型状态。ZeRO 逐步将越来越多的状态分区：

| 阶段 | 分区到数据并行工作节点 |
| --- | --- |
| ZeRO-1 | 优化器状态 |
| ZeRO-2 | 优化器状态和梯度 |
| ZeRO-3 | 优化器状态、梯度和参数 |

使用八个工作节点，理想情况下均匀分区的状态在每个工作节点上占据八分之一。激活、缓冲区和临时收集的参数不一定按这个因子缩小。

## 内存节省与通信交换工作

ZeRO-3 在计算需要时收集参数，并根据执行计划释放/重用存储。卸载可以将选定状态放在 CPU 内存或 NVMe 上，增加传输成本。最佳配置取决于互连带宽、主机内存、存储、批量大小和重叠——而不仅仅是最高阶段编号。

激活检查点通过在反向过程中重新计算激活来解决不同的内存组件问题。张量并行性和管道并行性以其他方式划分计算。这些技术可以共存，但需要一致的进程组和批量计数。

## 一个说明性的配置

```json
{
  "train_micro_batch_size_per_gpu": 2,
  "gradient_accumulation_steps": 8,
  "zero_optimization": {"stage": 2}
}
```

这是一个配置片段，而不是完整的训练程序。使用四个数据并行工作节点，其有效批量为 $2\times8\times4=64$ 每个优化器步骤的示例，假设普通的数据并行累积。指定优化器、精度、启动器和模型集成以进行实际运行。

**练习。** ZeRO-1 是否移除重复的梯度？不；这在 ZeRO-2 中添加。ZeRO-3 是否使检查点保存与单设备训练相同？不；确保所选的保存/合并程序捕获所需的分片。
