# 🧠 DeepSeek-R1：61 层 MLA 与等长逐层缓存

完整 DeepSeek-R1 的主干有 **61 层**：前 3 层使用 Dense FFN，后 58 层使用 MoE；各层 MLA 的缓存维度相同。对于同一段 128 Token、BF16 缓存，每层都是 **128 KiB 潜在 KV + 16 KiB RoPE K**。

??? note "配置、实现与适用范围"

    本页绑定 `deepseek-ai/DeepSeek-R1@56d4cbbb4d29` 的[官方配置](https://huggingface.co/deepseek-ai/DeepSeek-R1/blob/56d4cbbb4d29f4355bab4b9a39ccb717a14ad5ad/config.json)，并保留[原始配置快照](../../../../assets/model-specs/deepseek-r1.config.json)。MLA 的展开与吸收式缓存布局参照固定版本的 [DeepSeek-V3 官方实现](https://github.com/deepseek-ai/DeepSeek-V3/blob/b15f0dbbbe6a4bc403306175698439ef380f5fb5/inference/model.py)，与 R1 配置中的 `DeepseekV3ForCausalLM` 架构对应。以下是未做 TP/EP 切分的逻辑 shape，权重写作 `[out,in]`；本页不适用于采用 Qwen/Llama 架构的 R1 蒸馏型号。

## 🗺️ 全局配置与逐层分工

| 配置 | 值 |
| --- | --- |
| 词表 / 隐藏宽度 / 主干层数 | 129280 / 7168 / 61 |
| FFN 分布 | 层 0–2 为 Dense，层 3–60 为 MoE |
| Dense / 单专家中间宽度 | 18432 / 2048 |
| 路由专家 / 每 Token 选中 / 共享专家 | 256 / 8 / 1 |
| Query 头 / NoPE + RoPE / Value 头宽 | 128 / 128 + 64 / 128 |
| Q 低秩 / KV 潜在维度 | 1536 / 512 |
| 最大位置数 / 额外预测层数 | 163840 / 1（不计入 61 层主干） |

每层依次执行归一化、MLA、残差，再执行归一化、Dense FFN 或 MoE、残差。层间输入和输出均为 `[B,S,7168]`。FFN 类型变化不会改变同一 Token 块的主缓存大小。R1 没有 GLM 的独立 DSA indexer K，也没有 V4 的 CSA/HCA 压缩倍率交替。

Embedding 与未绑定的 LM Head 权重分别为 `[129280,7168]`；保留全部本轮位置的 logits 时，输出为 `[B,S,129280]`。

## 📐 MLA 投影与激活 Shape

下表采用所引 DeepSeek 参考代码的模块名称；其他实现可能使用 `q_a_proj` 等等价命名。

| 模块 | 逻辑权重 shape | 输出或逻辑激活 shape |
| --- | --- | --- |
| `wq_a` / Q RMSNorm | `[1536,7168]` / `[1536]` | `[B,S,1536]` |
| `wq_b` | `[24576,1536]` | `[B,S,128,192]` |
| Q 的 NoPE / RoPE 切片 | 无独立投影 | `[B,S,128,128]` / `[B,S,128,64]` |
| `wkv_a` | `[576,7168]` | 潜在 KV `[B,S,512]` + 共享 RoPE K `[B,S,64]` |
| KV RMSNorm | `[512]` | `[B,S,512]` |
| `wkv_b` | `[32768,512]` | 逻辑 K-NoPE `[B,S,128,128]` + V `[B,S,128,128]` |
| K 拼接共享 RoPE 后 | 无新增权重 | `[B,S,128,192]` |
| Attention 输出拼头 | 无新增权重 | `[B,S,16384]` |
| `wo` | `[7168,16384]` | `[B,S,7168]` |

`24576 = 128 × (128 + 64)`，`32768 = 128 × (128 + 128)`，`16384 = 128 × 128`。128 个 Query 头不意味着必须保存 128 份潜在 KV；吸收式 MLA 保留共享潜在向量与共享 RoPE K，结合投影权重完成各头的打分和输出。

## 🧩 Dense 与 MoE

层 0–2 的 Dense gate/up 权重各为 `[18432,7168]`，down 为 `[7168,18432]`，中间激活为 `[B,S,18432]`。层 3–60 的 Router 权重为 `[256,7168]`，为每个 Token 选择 8 个路由专家。

单个专家的 gate/up 权重各为 `[2048,7168]`，down 为 `[7168,2048]`；专家中间激活为 `[N_e,2048]`，`N_e` 是实际路由到该专家的 Token 数。共享专家维度与单个路由专家相同，对该层所有 Token 计算。专家激活不进入下面的 KV 传输字节公式。

## 📦 为什么是 `61 × (128k + 16k)`

这里 `k` 表示 KiB。假设采用吸收式 MLA、缓存按 BF16 存储，每个 key 覆盖 128 个原始 Token：

| 每个模型层拥有的缓存 | 一个块的逻辑 shape，省略 batch | 有效字节量 |
| --- | --- | ---: |
| 潜在 KV | `[128,512]` | `128 × 512 × 2 = 128 KiB` |
| RoPE K | `[128,64]` | `128 × 64 × 2 = 16 KiB` |

因此每层为 `144 KiB`，61 层共 `8784 KiB = 8.578125 MiB = 8,994,816 Byte`。**61 个模型层的缓存总大小都相同；128k 与 16k 是同一层内的两种组件。**

```text
层 0： [128k 潜在 KV, 16k RoPE K]
层 1： [128k 潜在 KV, 16k RoPE K]
……
层 60：[128k 潜在 KV, 16k RoPE K]
```

[MMC benchmark 的固定预设](https://github.com/nbbb24/self_test/blob/2a7ca1333ac3ce5710764ba84d75850b1586b520/mmc_benchmark/model_profiles.py)将每层拆成两段，单个 key 的大小列表为 `[131072,16384] × 61`，共 **122 个 buffer 段**。相同大小的段可归入两个 `uint8` tensor：`[61,B,131072]` 和 `[61,B,16384]`；这里 B 是批量 IO 的 key 数。若每层合并成一段，则为 61 段、每段 144 KiB，总字节量相同，地址分段不同。

128k 不是完整 K、16k 也不是完整 V；二者共同表示 MLA 的压缩 KV 状态与独立 RoPE K，不再额外乘一个 K/V 的 2。BF16 的每元素 2 字节已经计入公式。

## 🔄 物理布局与并行边界

参考代码的 `naive` 路径保存展开的各头 K/V，`absorb` 路径保存 `[B,T,512]` 和 `[B,T,64]`。上述公式绑定后者；权重配置中的 FP8 不能直接推导缓存也按 FP8 存储。

公式不含量化 scale、padding、对齐、页表、工作区、MTP 或运行时副本。PP 只计算当前阶段实际拥有的层；TP 是否复制共享潜在 KV，要按所用后端核对，不能将公式机械除以 TP 数。

这个 benchmark 只模拟随机字节与分散地址的 put/get 负载，不执行 Attention 或 FFN。各型号的同口径公式见[结构汇总](index.md)。
