# 🔧 适配器：用少量参数适配新任务

全量微调为每个任务创建一个完整的更新模型。相反，适配器在大量冻结的网络中插入小的可训练模块。基础模型可以共享，而每个任务存储自己的紧凑附加。

## 🧮 瓶颈计算

一个常见的适配器将隐藏宽度 $d$ 下降到较小的宽度 $r$，应用非线性，然后映射回来：

$$
h'=h+W_{up}\,\phi(W_{down}h+b_{down})+b_{up}.
$$

主要权重计数为 $2dr$，与平方密集矩阵的 $d^2$ 相比要少。当 $d=768$ 和 $r=64$ 时，每个适配器有 98,304 个权重（不包括偏置）。放置和每层的适配器数量决定了总权重。

残差路径和接近恒等初始化有助于在开始时保留预训练行为。插入的非线性计算赋予了适应自己的容量。根据食谱，层归一化参数或任务头部也可能被训练；记录实际可训练参数列表。

## 🛠️ 实际应用场景

一个共享编码器用于情感分类和支持工单路由。每个任务加载自己的适配器和分类器，同时保留相同的基权重。这减少了检查点存储和优化器状态内存，但基础模型仍然必须加载并执行。

## 📌 与 LoRA 的权衡

瓶颈适配器通常在推理路径上添加操作。LoRA 学习一个低秩权重更新，有时可以合并到兼容的密集权重中。这两种方法都不能保证在每个任务上的全量微调质量。在相同的数据、学习率搜索和评估预算下进行比较。

冻结一层并不意味着在训练过程中可以跳过其所有中间计算：梯度可能需要通过它到达更早的适配器。因此，激活内存仍然可能相当大。

**练习。** 如果 24 个适配器每个包含 98,304 个权重，存储了多少个适配器权重？在偏置和头部之前是 2,359,296 个权重。这个计数与冻结的骨干网络分开。
