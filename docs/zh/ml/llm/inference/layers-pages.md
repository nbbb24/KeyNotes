# KV 缓存布局：层、页与物理缓冲区

逻辑缓存通过请求、层、标记、头部和特征进行索引。物理布局决定了哪些值在内存中是连续的。计算和缓存传输可能更喜欢不同的布局，因此单个形状本身不能解释性能。

## 三个说明性的顺序

假设行主序连续存储，并且有一个单独的前导K/V轴：

| 布局 | 示例轴 | 自然分组 |
| --- | --- | --- |
| 层优先 | `[KV, layer, page, token_in_page, head, dim]` | 一个层的标记块 |
| 标记优先 | `[KV, page, token_in_page, layer, head, dim]` | 页面内层之间的单个标记 |
| 页面后层 | `[KV, page, layer, token_in_page, head, dim]` | 页面内的每层块 |

对于两个层和每页四个标记，页面-然后-层存储 `L0:t0,t1,t2,t3` 后跟 `L1:t0,t1,t2,t3` 在每个K/V页面区域内部。标记优先交错 `t0:L0,L1`，然后 `t1:L0,L1`，依此类推。它们包含相同的逻辑值，但步长不同。

一个特定层的注意力内核通常从按层访问中受益。将整个前缀块卸载到层之间可能更有利于按页面分组。K和V仍然可以是单独的缓冲区，因此“一页”不一定意味着一个连续传输包含所有内容。

## MLA使用不同的存储组件

MLA缓存可以存储压缩的潜在状态和一个单独的旋转键组件，而不是每个头部的完整K/V张量。对于说明性的潜在宽度512和旋转宽度64，两个缓冲区可能具有形状 `[pages, layers, page_size, 1, 512]` 和 `[pages, layers, page_size, 1, 64]`。实现中的名称如 `k_buffer` 和 `v_buffer` 并不能证明其内容是普通的注意力键和值。

术语如 `page_first_direct` 或 `page_first_kv_split` 是框架/版本特定的标识符。验证所用版本的实际步长、数据类型、分配和内核合同。一个系统的“L3缓存层”可能意味着远程/存储支持的KV缓存，而不是CPU的硬件L3缓存。

## 测量完整路径

包括布局转换内核、收集/分散操作、DMA粒度、对齐和同步。更快的存储传输如果在每次注意力调用前重新打包都昂贵，则会失去其优势。使用代表性前缀长度和重用率。

**练习。** 交换张量的逻辑维度是否总是移动其字节？不是。一个视图可能只改变步长；连续转换才执行实际的数据移动。
