# 🖼️ 多模态学习：如何结合不同输入

一种模态是一种观察形式：文本、图像、音频、视频或传感器信号。多模态学习询问如何表示、连接和一起使用它们的信息。添加第二种模态只有在它贡献可使用的信息并且学习过程可以利用它时才有帮助。

## 🧭 问题地图

![多模态学习：如何结合不同输入：原图 1](../../../../assets/notion/023-00.png)

原始的地图将表示、对齐、推理、生成、转移和量化分开。这些问题相关但不是强制性的线性流程。

| 问题 | 具体示例 | 需要测试的内容 |
| --- | --- | --- |
| 表示 | 将图像块转换为向量 | 编码器保留的信息 |
| 对齐 | 将标题与图像匹配 | 检索排名和硬负样本 |
| 融合/推理 | 回答关于图表的问题 | 跨模态交互，而不是文本捷径 |
| 生成 | 从图像生成标题 | 地基、覆盖范围、不支持的声明 |
| 转移 | 使用文本监督提高视觉表现 | 在有限视觉标签的情况下性能 |
| 量化 | 测量互补性和鲁棒性 | 削减实验、缺失模态、不确定性 |

## 🧩 跟随一个视觉问题

对于“左边的车是什么颜色？”这个问题，系统必须定位一辆车，解决`左边`，识别颜色，并表达答案。全局图像/文本相似度评分可能在不解析那个空间关系的情况下识别总体主题。需要细粒度交互或合适的训练数据。相反，从包含一百万项的集合中检索可能的图像受益于可以预先索引的独立嵌入。

## 📌 对齐不是融合

[对齐](alignment.md)建立对应关系。[融合](fusion.md)结合信息进行预测。一个双编码器可以在不进行标记级别交互的情况下对齐。一个跨注意力网络可以在不强制每个表示进入同一个相同度量空间的情况下融合模态。

## 🚀 构建有信息的基线

在相同的分割下比较文本-only、图像-only、简单的后期融合和提出的多模态系统。在评估时移除或打乱一种模态。如果性能几乎没有变化，模型可能忽略它——或者数据集可能不需要它。用任务特定的例子区分这些可能性。

**练习。** 添加标题后性能的提高是否证明了视觉推理？不是。标题可能会直接揭示标签。检查是否有意的视觉证据仍然必要。
