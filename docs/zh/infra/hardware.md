# 加速器硬件：从硅片到内核执行

CPU、GPU、NPU 是有用的设计分类。CPU 强调灵活控制和低延迟执行，GPU 强调并行吞吐，NPU 针对张量和神经网络操作进行较强特化。实际支持哪些操作、性能如何，取决于架构、软件栈、数据类型和工作负载。

## 不要混淆物理与逻辑边界

Die 是硅片单元，Package 将一个或多个 Die 封装起来，Card 承载器件。Device 是运行时枚举出来、可以提交任务的对象。分布式 Rank 是通信组内部的身份。这些概念之间不存在通用的一一对应关系。

排障时建立一张映射表：`Rank → 进程 → 主机 → 运行时 Device → 物理位置 → 通信端点`。作业如果重排了可见设备，运行时 Device 0 不一定是最初编号为 0 的物理设备。

## AI Core 怎样接收工作

从概念上看，Host 软件准备内存并启动内核，设备侧协调搬运和计算。Matrix/Cube 单元执行受支持的矩阵操作，Vector 单元执行向量及逐元素操作，标量和控制逻辑组织执行。AICPU 是设备侧辅助处理器，与上述计算单元不同。

MTE 在受支持的存储层级之间搬运计算块，还能完成部分布局转换。HBM 或全局内存存储大张量，片上缓冲区保存更小、更靠近计算单元的工作集。矩阵与向量资源的耦合方式随后代变化，必须将[昇腾架构文档](https://www.hiascend.com/doc_center/source/en/canncommercial/800/opdevg/tbeaicpudevg/atlasopdev_10_0008.html)与目标产品对应起来。

## 为什么要分块计算

矩阵乘法 $C=AB$ 如果不断从全局内存重复读取相同元素，就会浪费带宽。将一个 Tile 加载到局部存储后，可以复用于多次乘加。更大的 Tile 可能提高复用率，但也占用更多局部内存，并可能降低并发度。高效内核需要在复用、占用率、布局和同步之间平衡。

粗略 Roofline 模型为 $P\le\min(P_{peak},B\times I)$，其中 $I$ 是相对于所测内存层级的每字节运算数。若 $B=1$ TB/s、$I=10$ FLOP/byte，即使计算峰值更高，该内存层级也最多支持 10 TFLOP/s。这是说明模型的假设数值，不是昇腾规格。

## 先观察，再归纳

记录设备型号、驱动与运行时、可见设备数、PCIe 或专用互联拓扑、NUMA 关系和内存容量。仅凭 A2、A3、A5 等产品家族名称，无法推断 Die 数、一致性和通信协议支持。若流水线受限于搬运或不支持算子的回退，提高矩阵单元速度也无法直接解决问题。
