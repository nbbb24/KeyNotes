# 🌐 GVA 统一编址原理

[页表与大页](page-tables-huge-pages.md)解释了一个地址空间中的虚拟地址如何转换为物理地址。本章接着回答另一个问题：当内存分散在不同进程、设备和节点时，上层应用怎样统一描述和定位这些资源？先认识 GVA，再沿着“资源定位 → 解析访问信息 → 执行访问”的顺序理解它。

## 1. 什么是 GVA？

GVA（Global Virtual Address，全局虚拟地址）是一种统一内存编址机制，用于将不同进程、不同设备、不同节点的内存资源纳入统一的地址空间。

更严格地说，GVA 是这套机制使用的全局地址表示；“GVA 统一编址”指围绕这种地址建立的资源管理与访问机制。

在 MemFabric 中，参与内存池化的资源可以包括：

- **Host DRAM**：CPU 侧内存，通常通过 HVA（Host Virtual Address）访问。
- **Device HBM**：NPU 侧内存，通常通过 DVA（Device Virtual Address）访问。

传统情况下，不同进程、不同设备具有各自独立的虚拟地址空间。例如，进程 A 的 HVA 不能直接用于访问进程 B 的内存，CPU 也不能直接通过普通 HVA 访问 NPU HBM。这里指没有建立相应共享或设备映射的情况；能否访问，仍要由当前上下文中的有效映射、权限及硬件能力决定。

GVA 的作用是为这些分散的内存资源建立统一的全局地址表示，使上层应用能够通过 GVA 描述和定位池化内存，而不必直接管理底层的 HVA、DVA 及设备位置。

这里的“全局”应理解为**参与同一内存池或管理域的资源之间具有一致的地址表示**，并不是任意机器、任意进程都能直接访问。MemFabric 的池化与全局统一编址设计可参见[项目说明](https://github.com/Ascend/memfabric_hybrid/blob/master/README.md)。

## 2. GVA 如何实现统一编址？

假设系统存在两个进程，分别管理不同的 DRAM 和 HBM：

```text
                 GVA 全局地址空间
┌────────────────────────────────────┐
│ GVA 区域 A → 进程 A 的 Host DRAM    │
│ GVA 区域 B → 进程 A 的 Device HBM   │
│ GVA 区域 C → 进程 B 的 Host DRAM    │
│ GVA 区域 D → 进程 B 的 Device HBM   │
└────────────────────────────────────┘
                   │
                   ▼
            全局内存映射信息
                   │
         ┌─────────┴─────────┐
         ▼                   ▼
      进程 A                进程 B
    ┌────────┐            ┌────────┐
    │  DRAM  │            │  DRAM  │
    │  HBM   │            │  HBM   │
    └────────┘            └────────┘
```

GVA 并不意味着所有内存被搬迁到同一位置，而是通过全局地址管理，将不同物理位置的内存组织成统一的逻辑地址空间。

其核心关系可以概括为：

**GVA → 内存资源定位信息 → 底层地址或内存句柄 → 实际数据访问**

读图时，可以按三个问题逐步理解：

1. **地址表示的是哪一段资源？** 例如，区域 D 对应进程 B 管理的 Device HBM。
2. **这段资源实际位于哪里？** 映射信息描述所属节点、进程、设备、内存类型及区域等。
3. **当前访问者怎样到达它？** 还需要后端支持的地址映射、访问句柄或传输资源。

图中的“全局内存映射信息”表示逻辑上的对应关系，不要求实现中只有一张集中式总表，也不表示每次读写都必须跨网络查询一次。理解概念时，应将资源身份与实际访问路径分开。

## 3. 通过 GVA 如何访问内存？

假设应用需要通过某个 GVA 访问远端 NPU 的 HBM，概念上的处理流程如下：

1. **获取 GVA**：应用使用 GVA 指定目标内存区域及偏移。
2. **定位内存资源**：根据 GVA 查找对应的节点、设备、内存类型及内存区域。
3. **解析底层访问信息**：获取传输所需的本地或远端地址、注册内存信息、访问句柄等。
4. **选择传输方式**：根据源、目的内存位置及系统配置，选择合适的传输机制，例如 SDMA、RDMA 或 URMA 相关路径。
5. **执行数据访问**：由底层传输引擎完成数据读写或拷贝。

需要注意，GVA 不一定在每次访问时都转换成 HVA 或 DVA，也可能通过设备映射、DMA 地址或注册内存句柄等方式完成访问。具体取决于底层实现。

**术语说明：**上面的 SDMA、RDMA、URMA 保留为访问路径的例子，但不应理解成同一层次的三个网络协议。SDMA 是搬运引擎，RDMA 是远程内存访问机制，URMA 提供统一远程内存访问的接口与语义。某个组合是否支持远端 HBM，还要核对硬件、后端和内存类型；见 [MemFabric 架构说明](https://github.com/Ascend/memfabric_hybrid/blob/master/README.md)、[openEuler UMDK 的 URMA 介绍](https://gitee.com/openeuler/umdk/blob/master/README.md)及[互联与通信](interconnects.md)。

### 走一遍例子：进程 A 读取进程 B 的 HBM

沿用上图，假设区域 D 的 GVA 起点记为 `G_D`，应用要读取偏移 `0x2000` 开始的 `0x1000` 字节，并写入进程 A 的本地 DRAM 缓冲区：

```text
源资源标识：GVA = G_D + 0x2000
源资源归属：进程 B 所在节点 → 对应 NPU → 区域 D 的 Device HBM
访问长度：  0x1000 字节
目标缓冲区：进程 A 中已经分配且满足后端访问要求的 Host DRAM

定位源资源
  → 取得源、目标的后端访问信息
  → 选择受支持的直达或中转路径
  → 提交读操作或拷贝
  → 等待所需完成状态并满足可见性要求
  → 进程 A 消费本地缓冲区中的数据
```

`G_D` 是本例用于说明区域起点的符号，不是对真实 GVA 位编码的规定。若后端为这段资源建立了 DVA 映射，该位置可能对应 `D_B + 0x2000`；另一个后端也可能使用注册内存描述来定位它。**知道 GVA 不等于取得了可用 DVA，也不等于已经获得访问权限；使用注册内存描述的后端则应核对相应描述的有效性。**

在接口层，MemFabric 的 BM 文档展示了取得 GVA 后调用拷贝接口的使用方式，SHM 则提供受支持的设备侧访问方式，不能把所有路径都当成一次普通 CPU 指针读取。参见 [BM、TRANS 与 SHM 特性介绍](https://github.com/Ascend/memfabric_hybrid/blob/master/doc/feature.md)。

执行访问还包括完成与生命周期约束：提交成功不一定表示目标数据已经可供应用消费；操作尚在途时，相关内存、映射和注册句柄必须保持有效。进一步的完整过程见[端到端传输](end-to-end-transfer.md)。CPU 虚拟地址与设备 DMA 地址的区别可参见 [Linux DMA API 指南](https://docs.kernel.org/core-api/dma-api-howto.html)。

## 4. GVA 与页表有什么区别？

| 概念 | 作用 |
| --- | --- |
| VA | 虚拟地址的统称 |
| HVA | Host 进程使用的虚拟地址 |
| DVA | NPU 设备侧使用的虚拟地址 |
| GVA | 用于统一定位池化内存的全局虚拟地址 |
| 页表（Page Table） | 管理虚拟页与物理页之间的映射 |
| PTE（Page Table Entry） | 页表中的一条映射记录 |

两者都涉及地址映射，但处于不同抽象层次：

- **页表**：主要解决 CPU 或设备虚拟地址到物理地址的转换问题。
- **GVA 统一编址**：主要解决跨进程、跨设备、跨节点的内存资源如何统一寻址的问题。

因此，GVA 不等同于 CPU 的虚拟地址，也不意味着应用能够直接通过普通 CPU 指针解引用任意 GVA。

**抽象层次不同，并不表示实现上互不相关。** MemFabric 的全局内存管理可以制定页表映射策略，并通过驱动将策略落实到页表中。因此，GVA 描述的资源可能最终借助硬件映射完成访问；GVA 本身仍不是一张硬件页表。这个联系可对照 [MemFabric 的 Global Memory Management 模块说明](https://github.com/Ascend/memfabric_hybrid/blob/master/README.md)理解。

如果还不熟悉“虚拟页 → 页表项 → 物理页 → 页内偏移”的过程，可以回看[页表、PTE、大页与地址转换](page-tables-huge-pages.md)。

## 5. 总结

GVA 统一编址的本质，是**为分布在不同进程、不同设备及不同节点上的 DRAM、HBM 建立统一的逻辑地址空间，并通过映射关系定位底层内存资源，最终由相应的传输机制完成数据访问。**

可以从三个层面理解：

- **统一编址**：不同位置的池化内存使用统一的 GVA 地址体系。
- **资源定位**：通过 GVA 确定目标内存所属的节点、设备及内存区域。
- **数据访问**：通过 HVA、DVA、内存注册信息或其他底层机制完成实际访问。

**GVA 统一的是地址表示和资源寻址方式，而不是物理内存的位置，也不能直接等同于硬件页表。**

继续阅读[内存与地址](memory-addressing.md)，可以将这些概念与虚拟地址预留、物理内存分配、映射、注册和回收联系起来。
