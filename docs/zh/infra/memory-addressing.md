# 内存与地址：字节在哪里，谁可以访问

一个数值地址，只有放进具体地址空间才有意义。两个进程可以用相同的虚拟地址表示不同存储；设备访问 Host 内存之前，也可能需要映射或注册。这就是为什么复制指针值并不等于共享缓冲区。

## 容量、局部性与持久性

| 存储 | 典型用途 | 主要问题 |
| --- | --- | --- |
| AI Core 局部缓冲区，L0/L1/UB | 计算块及中间结果 | 工作集能否放进支持的存储层级？ |
| 设备全局内存，常见为 HBM | 权重、激活、KV Cache | 限制来自容量还是带宽？ |
| Host DRAM | 输入暂存、Offload、大容量内存池 | 内存是否靠近设备的 I/O 路径？ |
| 远端内存 | 共享或解耦容量 | 访问延迟与故障语义是什么？ |
| SSD 与存储系统 | 持久化数据、Checkpoint | 访问是顺序、随机，还是命中缓存？ |

AI Core 的 L1 是硬件缓冲区；分层 KV Cache 中的“L1 缓存”是软件抽象。类似地，片上 Unified Buffer 与 Unified Bus 的缩写相同，功能并不相同。

## 一个资源，多个地址空间

CPU 的 MMU 将进程虚拟地址 VA 转换到物理存储 PA，并实施权限保护。设备可能使用由 IOMMU 转换的 I/O 虚拟地址 IOVA。在受支持的系统上，Shared Virtual Memory 可以简化寻址，但不会消除数据迁移、一致性、权限和顺序要求。

在分布式内存管理器中，**统一编址**指资源可以在共享的*逻辑*地址空间中拥有稳定身份，不代表各机器的物理内存变成一个自动保持一致性的堆。以 [MemFabric Hybrid 的实现](https://gitcode.com/Ascend/memfabric_hybrid)为例，需要区分：

| 名称 | 标识什么 | 谁能直接使用？ |
| --- | --- | --- |
| GVA（Global Virtual Address） | 跨参与方标识受管理内存片段的逻辑地址或偏移 | 内存管理器及其转换、传输 API；它**不是**可到处解引用的指针 |
| HVA（Host Virtual Address） | 某个进程 CPU 虚拟地址空间中的地址 | 建立有效映射并有访问权限的那个进程 |
| DVA（Device Virtual Address） | 某个设备上下文中的虚拟地址 | 后端内存与映射有效时的设备或运行时 |

例如，一个缓存片段可用 GVA `G+0x2000` 标识，而进程 A 看到的 HVA 是 `H_A+0x2000`，设备 B 看到的 DVA 是 `D_B+0x2000`。这几个数值不必相等；查询或映射才建立它们之间的关系。只发送 GVA 不会授予对字节的访问权。不同后端的转换关系也可能不同，因此必须核对 API 与内存类型。MemFabric 源码中的 Host、Device 传输路径会按需显式地将 GVA 转换为 HVA 或 DVA。

## “分配内存”其实是一段生命周期

日常所说的“分配”常常掩盖多个独立步骤。将它们拆开，才能理解为什么可预留的地址范围可能远大于实际 HBM 容量。

1. **预留虚拟地址范围。** 在地址空间中选取足够大且对齐的区域。此时占用的是*地址*，不一定已经占用 HBM 或 DRAM 物理页。预留失败可能来自地址空间不足、碎片或对齐限制。
2. **创建或取得后端内存。** 运行时分配设备物理内存、Host 页，或取得可共享的分配句柄。物理页何时真正提交，取决于分配器和后端；不能因为“预留成功”就断定它们已提交。
3. **建立映射。** 把物理页或句柄关联到所选 DVA/HVA 范围，并设置设备、上下文和访问权限。映射及后端内存失效后，地址也不能继续使用。
4. **按需注册或导出。** DMA/RDMA 或对端设备可能还需要注册、固定页面、导入或访问描述。注册是准备访问条件，不是在复制数据。供 DMA 使用的 Host 内存也可能需要不同于普通可换页 `malloc` 缓冲区的处理。
5. **使用并同步。** 提交任务，等待相应的完成事件，并在另一条流、另一设备或进程消费数据前满足可见性要求。
6. **按依赖关系逆序回收。** 停止新增使用者；等待在途任务；释放导入映射与注册；解除映射；释放后端内存；最后释放预留 VA。每种句柄都应有明确所有者。

```mermaid
flowchart LR
    A[预留 VA<br/>不代表已有物理内存] --> B[获取 HBM 或 DRAM 后端内存]
    B --> C[建立映射及权限]
    C --> D[按需注册或导出]
    D --> E[提交并等待完成]
    E --> F[注销注册、解除映射]
    F --> G[释放后端内存和 VA]
```

这是概念上的生命周期，不要求所有后端采用完全相同的调用顺序：有的分配器会合并步骤，导入操作也可能映射别人分配的内存。[MemFabric Hybrid API](https://gitcode.com/Ascend/memfabric_hybrid)将虚拟空间预留、片段分配和 GVA→VA 转换分开；内部 VA 管理器记录片段的 GVA、DVA、HVA、大小和内存类型。记录只是元数据，实际访问仍需有效映射与权限。

### 一个预留与真正分配的例子

假设服务先为缓存池预留 **64 GiB** 设备 VA 窗口，只用 HBM 为其中 **8 GiB** 提供后端内存。服务可以在已映射的 8 GiB 内分配逻辑位置，但访问其余未映射的 56 GiB 是无效的。后续扩容仍需取得更多后端内存并建立映射，受空闲 HBM 和运行时限制。释放 8 GiB 后端内存，也不等于把整个虚拟窗口还给其他分配器；预留还要单独释放。反过来，DMA 尚在使用映射片段时提前释放预留范围也不安全。这些数字仅用于解释区别，不是设备配置建议。

## 地址转换与访问准备

片段需要供另一进程或设备使用时，应交换后端支持的描述，其中包含足够的身份、大小、类型及访问权限信息。接收方导入后建立*自己的*映射。GVA 可以帮助定位片段，却不能替代导入或传输协议。通信顺序见[端到端传输](end-to-end-transfer.md)。

## NUMA 让内存放置影响性能

多 Socket 系统中，CPU 访问本地和远端 DRAM 的代价可能不同。靠近 NUMA 0 的设备，访问 NUMA 0 缓冲区可能比访问 NUMA 1 更高效。CPU 亲和性本身不保证内存放置：分配策略和首次触碰行为也有影响。

测试 Host Offload 时，记录提交线程所在 CPU、缓冲区实际放置、设备 PCIe 位置和网卡位置。在其他条件一致的情况下比较本地、远端放置。带宽下降可能来自 Socket 互联，而不是加速器链路。

## 按证据诊断无效地址

看到 `TransformVa no mapping`，先确认当前上下文中是否建立了预期映射。注册失败时，检查内存类型、地址、长度、对齐、权限、后端支持和资源限制。导入失败时，检查句柄来源、内存类型和导出方生命周期。即使指针落在有效分配内，`offset + length` 越界仍然会失败。

明确谁负责分配、注册、提交、等待和释放资源。超时后，先确定操作已取消还是仅仅尚未观察到完成，再决定能否释放内存。结合[异步复制](data-movement.md)与[传输流程](end-to-end-transfer.md)理解这些约束。
