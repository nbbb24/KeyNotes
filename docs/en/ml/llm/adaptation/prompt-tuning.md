# 💬 Prompt tuning, prefix tuning, and P-tuning

These methods optimize continuous parameters that condition a frozen language model. They differ from ordinary prompt engineering, where a person edits discrete text without gradient-based training.

| Method | Where the learned signal enters | Main idea |
| --- | --- | --- |
| Prompt tuning | Input embedding sequence | Prepend learned soft-token vectors |
| Prefix tuning | Layer attention states, commonly K/V prefixes | Give each layer learned virtual context |
| P-tuning v1 | Input-level continuous prompts generated by an encoder | Parameterize soft prompts with an LSTM/MLP-style encoder |
| P-tuning v2 | Deep prompts across layers | Extend prompt adaptation to deeper model states |

## 🧮 Count the simplest case

An input soft prompt of length $m$ and hidden width $d$ has $md$ parameters. With $m=20$ and $d=4096$, this is 81,920 learned values. Prefix tuning can require separate layerwise K/V states, so its count also depends on layer count and attention dimensions. A reparameterization network can change the training-time count.

## 💡 Why virtual tokens work

The frozen model is differentiable with respect to its inputs. The training objective adjusts soft vectors to steer the model toward useful behavior even though the backbone weights remain fixed. These vectors need not correspond to readable vocabulary words. A learned prompt is tied to the base model, tokenizer/template conventions, and injection mechanism used during training.

For a classification task, the soft prompt can condition the model to output label words. For generation, prefixes can influence every decoder layer. Additional insertion points offer flexibility, but do not guarantee superior accuracy or stability on every dataset.

## ⚠️ Costs and pitfalls

Virtual tokens consume attention context and may add KV-cache storage. Parameter efficiency does not imply zero inference overhead. Initialization, prompt length, model scale, optimization settings, and label verbalization affect results. Compare with LoRA and full fine-tuning under a reasonable tuning budget.

**Exercise.** Can a trained soft prompt always be copied into a text-only API prompt? No. It usually requires access to embeddings or internal attention states; it is not an ordinary string.
